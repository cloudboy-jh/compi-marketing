Get started#

Install Compi, open a shell and make your first split.

Windows

Windows x64 with WSL2 is required. Choose either:

  • Installer: run Compi-<version>-Setup.exe for a per-user installation with repair and uninstall. Compi-Setup.exe is the same installer under a stable name for the latest release.
  • Portable: extract the entire Compi-<version>-Windows-x64.zip archive together. Do not copy individual executables; the bundled terminal runtime and license must stay with the daemon.

macOS

Apple Silicon and macOS 14+ are required. Open Compi-<version>-macOS-arm64.dmg and drag Compi.app into Applications. Alternatively, extract Compi-<version>-macOS-arm64.app.zip and move the entire app bundle, not just its executable. Run the app from a writable location, not the mounted disk image, to allow updates. Native workspace qualification remains open.

Windows builds are unsigned and macOS builds are ad-hoc signed unless publisher credentials are configured; OS trust warnings may appear.

First-launch trust warnings

0.5.0 Windows packages are unsigned. The Mac app is ad-hoc signed, not notarized. For a download you trust, Windows may offer More info → Run anyway; on macOS try opening it, then use System Settings → Privacy & Security → Open Anyway. Do not disable operating-system security globally. Managed-device policy may prevent these overrides.

Your first workspace

  1. Launch Compi and open the palette with Ctrl + Shift + P, or Cmd + Shift + P on macOS.
  2. Choose New workspace to organize a project, then New terminal tab to start a shell.
  3. Choose Split right or Split down. New tabs and splits inherit the focused terminal’s reported directory.
compi split --right
compi --json pane list

Run those commands inside a Compi shell. Closing the app window keeps the server-owned shells running; closing a pane or restarting the server is different.

Using the palette and returning to the shell

The palette: Ctrl+Shift+P (Cmd+Shift+P on macOS) drops a search list down from the top of the window; nothing is dimmed, and a click anywhere outside it, or Esc, closes it without reaching the terminal. Type to search, in this order: Tabs (open tabs, and the panes of split tabs by name or folder), Commands, Projects (folders your shells visited; Enter opens a new tab there) and Files (the focused pane's folder, searched once you pause typing; Enter opens the file in the editor beside it). With nothing typed it lists recent tabs, every command by category and your most recent projects. Arrows choose, Enter runs. Open file… (Ctrl+Shift+O, Cmd+P on macOS) and Jump to project… open it showing only Files or Projects; remove that chip with its × or Backspace to search everything.

Views in place: Files, Settings and Monitor open in the pane you open them from (compi files, compi edit, compi diff, compi settings, compi monitor, or the palette). In a terminal pane the view replaces what the pane shows, using the whole pane, while the shell keeps running underneath at its size. Get back to the shell with Ctrl+Shift+E on Windows (Cmd+Shift+E on macOS; Toggle view in the palette), with Esc once the view has nothing left to close (a filter, the editor, a search, a highlighted card), or Show terminal in the pane menu; the same shortcut, Show Files (Settings, Monitor) in the pane menu, or the command again brings the view back with its open files and place kept. On a terminal without a view the shortcut shows the shell's current folder in a Files view. While the view shows, keys go to it, never to the shell. Each terminal carries one view; opening another kind replaces it, asking first about unsaved edits. The pane menu (right-click, or the ⋯ grip) also has Move to its own pane, which puts the view in a pane of its own beside the shell, and Close Files (or Close Settings, Close Monitor), which drops it. Views survive reconnects and restarts like the panes that carry them.

Workspaces and panes#

Organize projects into workspaces, tabs and panes without restarting their programs.

  • Workspace: a named group of tabs.
  • Tab: one terminal or a layout of split panes.
  • Pane: a terminal or content view that can be resized, moved, zoomed, floated or docked.

Move and arrange

Hover a pane for its ⋯ grip. Click for actions, or drag onto an edge to split beside another pane, the centre to swap, another tab to join it, or empty tab-bar space to make a new tab. Escape cancels.

Pane movement, floats and layout presets

Move a pane: Hover a pane to reveal the ⋯ grip in the middle of its top edge. Click it for the pane menu, or drag it to move the pane. Over another pane of the same tab, release on an edge to place the pane beside it, sharing that pane's space evenly, or on the centre Swap box to exchange the two; only the zone under the pointer is highlighted, the half the pane will take or the Swap box, over a faint preview of where the pane will land. Release on another tab to add the pane to it on the right; rest on a tab for a moment to switch to it while dragging, then drop beside one of its panes. Release on empty tab-bar space to give the pane its own tab. Esc, or releasing anywhere else, cancels. The shell keeps running: nothing restarts, and Restore previous pane arrangement undoes a move within a tab.

Float a pane: Right-click a pane, or click its grip ⋯, and pick Float pane (the palette has it too). The same running shell moves into a movable, resizable frame above the window and stays visible while you switch tabs or workspaces; its siblings fill the space it left, and the server's split layout is unchanged. Drag the title to move it and the right/bottom edges or corner to resize; the terminal is resized to fit. Dock pane (in the floating title's ⋯ menu, its right-click menu, or the palette) returns it to wherever its tab now places it without restarting anything. Docking never closes or ends work: closing a pane or tab is the separate Close pane/Close terminal tab action, and ending stays the explicit End process… action, which always asks first and keeps the final screen. Only one pane receives typing; a floating pane that has it has an accent border. To dock by dragging, drag the title onto a pane of the float's tab: release on an edge to place it beside that pane, or on the centre Swap box to take that pane's place (it takes the float's tile). Released anywhere else the float just moves; Esc puts it back. Click a pane or use Switch focus between floating and tiled panes / Focus next floating pane to move it. Floats are per window and are restored on relaunch.

Arrange panes and tabs: Run Arrange panes and tabs from the palette, or Arrange from a tab's right-click menu. Under Tabs to combine, click (or press Enter on) any other tab in this workspace to fold its panes into the current tab; click it again to leave that tab out. Built-in arrangements are Columns, Rows, Grid, Main + stack (side), Main + stack (top), and Equalize, which keeps the existing splits and evens their sizes; saved presets appear below them. Clicking or arrowing to a layout only previews it: the preview shows each pane's numbered place, across every combined tab, before anything moves. Double-click, Enter, or Apply commits it; Cancel, Esc, or clicking outside leaves everything as it was. M mirrors left/right and F flips top/bottom. Arranging only moves and resizes existing panes: no shell restarts and no pane is replaced. Combined tabs become one tab and disappear from the tab strip. Main + stack puts the focused pane in the large slot. A preset with fewer slots than panes stacks the extra panes in its last slot; a preset with more slots drops the unused ones. Mirror/Flip pane arrangement work directly on the current tab, Swap pane left/right/up/down exchanges the focused pane with its neighbor, and Restore previous pane arrangement undoes the last change: it restores the earlier layout, or, right after combining, splits the tabs back out (restoring a layout again swaps back). Split merged tabs back out recreates the combined tabs at any later time, with their names, order, and splits; panes you detached or removed since stay where they are. Save pane arrangement as preset stores the tab's split shape, never its terminals, in [layout_presets.NAME] of config.toml (up to 32 presets, 2–16 panes each; reusing a name replaces it); select a saved preset and press Delete twice to remove it. Floating panes keep floating and dock into their assigned slot. Swap commands have no default shortcuts; bind them under [keybindings], for example swap_pane_left = "ctrl-alt-left".

Hide, close or end?

ActionWhat happens
Close the app windowThe background server keeps running shells alive.
Hide a terminal tabThe tab’s processes keep running; restore it through the palette.
Close a pane or tabIts processes end. GUI close confirmation is optional and off by default.
End process…Asks first and leaves the terminal’s final screen visible.
Restart daemonAsks first and ends the server’s running shells.
Close confirmation settings

Closing a tab (its ×, Close terminal tab) or a pane (Close pane) ends its processes in one click. Settings → Interface → Confirm before closing asks first instead; Enter closes and Esc cancels. To keep a tab's processes running, hide it instead.

[workspace]
confirm_close = false

Removing a whole workspace and restarting the daemon always ask. The compi CLI keeps its own interactive confirmation.

Reconnect and recover

New tabs and splits open directly into the terminal canvas. Starting a shell shows no bar, spinner, delayed indicator, or reserved space.

Ended shells, launch failures, disconnected panes, and attachment conflicts retain their terminal canvas without recovery overlays, status buttons, or diagnostic hover cards. Final output and the last observed terminal name remain available after the shell ends. Use the existing pane-actions menu or command palette for explicit restart/attachment actions; inspect errors and exit codes through Diagnostics or compi --json pane show. Retrying attachment never takes control from another window. Reconnect window reconnects without restarting shells.

Shells that ended because Compi's background service restarted (for example after an update) come back on their own: the first time such a tab is on screen, it starts a fresh shell in the directory you were last in, or in its starting directory if that one no longer exists. Earlier output is gone. Shells you end yourself, or that fail to start, stay ended until you restart them.

Terminal scrolling and retained history
  • Scroll over a terminal pane without changing keyboard focus. While output continues, Compi keeps the text you are reading in place while it remains in retained history, including when older rows are evicted or a program redraws its history.
  • ↓ N new lines appears when output arrives while you are scrolled up. Click it, or type into the terminal, to return to live output.
  • Wheel and trackpad fractions accumulate per pane instead of rounding every event up. Applications with mouse reporting receive whole wheel reports; alternate-screen pagers such as less receive Up/Down keys otherwise. Programs can disable that fallback with DECSET 1007 (ESC[?1007l) and re-enable it with ESC[?1007h; it starts enabled.
  • Hold Shift to use local scrolling instead of sending wheel input to an application. Each pane keeps the configured history, 10,000 lines by default ([limits] scrollback_lines), within about 512 bytes per line on average; only unusually styled or wide output fills that sooner.

Files, editing and review#

Open the project’s files where you are already working.

compi files
compi edit
compi notes
compi diff

These open the relevant view in the current terminal’s pane while its shell keeps running underneath. Ctrl/Cmd + Shift + E toggles back. A file path can be passed to edit or notes; a repository is required for diff.

Edit and read Markdown

Use Edit / Read in a Markdown tab, or Ctrl/Cmd + E while the file view owns the keyboard. Read uses the same buffer, including unsaved edits. compi edit FILE forces Edit; compi notes FILE opens Read.

Save with Ctrl/Cmd + S, find with Ctrl/Cmd + F. Markdown supports tables, tasks, callouts, wiki links, backlinks, Mermaid and LaTeX.

Rendered tasks save the whole buffer.

Clicking a task checkbox saves the current buffer, including other unsaved edits, through the normal conflict-checked save.

Markdown behavior, notes search and rendering bounds

Markdown tabs have an Edit / Read switch in the tab's header (Edit / Read / Diff when the file has uncommitted changes), and Read Markdown (Ctrl+E, Cmd+E on Mac; a terminal keeps the key) switches between Edit and Read from the keyboard or the palette. Read shows the same buffer formatted, including unsaved edits; switching keeps your place, the line at the top of one mode at the top of the other, and from Diff Read opens at the line the diff shows. Tables, task lists, [!NOTE]-style blockquote callouts, fenced mermaid diagrams and $inline$ / $$display$$ LaTeX math render natively. Diagram and equation SVGs are prepared offline; they do not need a browser or downloaded packages. Unsupported syntax keeps its source with an error. Each window remembers which files you last read, across restarts, and opens them in Read however they open (tree, palette, a terminal link); others open in Edit. compi edit FILE opens Edit and compi notes FILE opens Read.

Clicking a rendered task checkbox saves the current buffer, including any other unsaved edits, through the editor's normal conflict-checked save. Read-only notes cannot be toggled; a file changed on disk shows the same conflict banner instead of being silently overwritten. The task edit remains undoable, and line endings are preserved.

Notes opens a panel below the document: empty search shows backlinks to the active note; typing searches the folder's Markdown files. Ctrl+F (Cmd+F) opens it from Read; the source editor keeps its own Find. A result opens its source line, and Esc closes the panel before returning to the terminal. The panel follows edits in open buffers; Refresh notes rereads other files from disk.

Rendering bounds: 128 distinct equations/diagrams per document, 8 KiB per equation, 64 KiB per diagram, 2 MiB per generated SVG and 4096 pixels per dimension. Larger resources show their source with the reason. Formula imports, filesystem access and package loading are unavailable.

compi notes search QUERY [FOLDER] searches note contents, filenames and heading titles case-insensitively and prints FILE:LINE: TEXT. compi notes backlinks FILE [FOLDER] finds source lines with [[target]] or [[target#heading|label]] links to FILE, ignoring inline, fenced and indented code. FOLDER defaults to the selected pane's current directory; FILE is relative to that notebook root, or absolute. Links resolve relative to their source note, then the notebook root, then a unique basename or heading title; missing or ambiguous targets are not guessed. Unix paths/titles are case-sensitive; Windows paths/titles ignore case. Heading suffixes do not change the resolved file.

Previews and file safety

Images and SVG have zoom/pan controls. PDF, audio and video use the system web view. Text over 1 MiB is read-only and paged in parts; syntax highlighting stops above 512 KB. Animated GIF and WebP show their first frame only.

Editor, previews, saves, conflicts and unsaved-edit recovery

Edit files: A content pane (opened with compi files or compi edit, see below, or from the palette, see the next item) shows its folder until you open a file: click a file, or select it with the arrow keys and press Enter. Type to filter the folder to matching names (Backspace edits the filter, Esc clears it); only folders you have expanded are searched. Hover the filter field for the keys. Open files appear as tabs above the editor; click a tab to switch, × to close it (a dot marks unsaved changes). Hover a tab for the file's full path and where it lives (host, WSL: Ubuntu, or SSH: host); the right end of the tab row names the same place. The folder button at the left of the tabs shows or hides the folder beside the file. The editor highlights syntax (files over 512 KB open as plain text, so typing stays quick), numbers lines and searches with Ctrl+F (Cmd+F); Ctrl+S (Cmd+S) saves, keeping the file's line endings. Images (PNG, JPEG, GIF, WebP, BMP, ICO, up to 64 MiB) open as images: fitted to the pane, the wheel zooms about the pointer, dragging pans, and the bar above shows the size with −, Fit, 100% and +. An SVG opens in the editor with Edit / View (Diff too when it has uncommitted changes); View (or Ctrl+E, Cmd+E) draws it, and Compi remembers which SVGs you last viewed. Text files over 1 MiB (logs, data dumps) open read-only about 1 MiB at a time, cut at line breaks: the bar says which part shows, and Start, Previous, Next and End move through the file; select, copy and Ctrl+F work within the part, and only the first part has line numbers. PDFs open in the system web view's PDF viewer, and audio and video files (MP3, WAV, FLAC, Ogg, M4A, MP4, WebM, …) in its player, whatever their size; playback pauses when you switch to another tab, and formats the web view cannot play say so. Other files that are not text show their size, path and a Copy path button instead of the editor. A read-only file opens read-only, marked Read-only on its tab; saving it offers Save as… instead. Compi never overwrites changes made outside it without asking: while a file is on screen, Compi checks it every couple of seconds. If it changed and you have no unsaved edits, the new text loads in place and the cursor stays where it was. If you have unsaved edits, a changed on disk note offers Reload (discard your edits) or Keep mine. If you save over a newer file anyway, the note offers Reload, Overwrite (replace what is on disk with your text) and Save as… (type another path; the tab switches to the new file and the original is left alone). A file deleted outside Compi keeps its text, and saving creates it again. Reload asks for a second click when it would discard edits. Closing never loses edits silently: closing a file tab, a pane, a tab or a workspace with unsaved files, moving such a tab to another window, closing the window, quitting, restarting the daemon or installing an update first lists the files and offers Save (Enter; if any file cannot be saved, nothing closes and its tab says why), Don't save and Cancel (Esc). Unsaved text is also kept on disk within a second of typing, so after a crash, an update restart or a reopened window the file comes back with your edits and a note Restored unsaved edits from … (plus the changed on disk note if the file changed meanwhile). Edits of files no longer open are offered by Recover unsaved edits… in the command palette, which opens the file beside the focused pane; kept edits are deleted after 30 days. Compi shortcuts (palette, splits, pane focus, sidebar, …) keep working while you type, Esc leaves the editor (or closes Save as) for the pane, and Enter or a click returns to it. Open files stay open across restarts.

Opening files from the palette, terminal paths and image cards

Open files from a terminal: In the command palette, Files shows the focused terminal's current directory in its Files view, in place of the shell; in a content pane it shows the pane's own folder (beside an open file, as the folder sidebar) and gives it the keyboard. New editor opens the Files view of a terminal without one, and otherwise a new content pane beside the focused pane. Open file… (Ctrl+Shift+O, Cmd+P on macOS) opens the palette on the focused pane's folder; type part of a file's path and Enter or a click opens it in the terminal's Files view, and nothing is typed into the terminal. Typing a file name in the full palette finds it too. Open file… searches WSL and Unix folders; for a native Windows folder use Files. All three need the terminal's directory: the one its shell last reported (OSC 7, see below), else the one it started in. A Files view keeps the files it has open; its folder moves to where a newly opened file lives when it does not hold it.

Open a file printed in a terminal: Ctrl-click (Cmd-click on macOS) a path such as src/main.rs, ./web/app.ts:4, /etc/hosts or crates/x/y.rs:12:3 (also File.cs(12,5)) to open it at that line in the terminal's Files view, in place of the shell. Relative paths start from the terminal's current directory, in its own environment (WSL or host). Compi first checks that the path is a readable file; otherwise it only shows a note. Web links keep opening in the browser, and file:// hyperlinks (OSC 8) open in the editor.

Paste a screenshot or image: Ctrl+V (Cmd+V) with an image on the clipboard, or dropping an image file on a terminal, types the image's path at the prompt and shows a card for it at the bottom right of that pane. Click the card to view the image over the window (zoom, Copy, Save). Right-click it for Open, Open in pane beside (the image in a Files pane split beside the terminal, read in the terminal's own environment), Copy path and Dismiss.

Diffs, staging and commits

Use Changes or compi diff to review uncommitted work. compi diff HEAD~1 opens a past commit, read-only, against its first parent. Unsaved buffer edits are not included in a disk-based diff.

Stage a file or hunk, write a commit message and use Ctrl/Cmd + Enter to commit. Discard changes… is destructive and asks first; discarding an untracked file deletes it.

Review, staging, commits and branch operations

Review changes: In a Git repository the folder sidebar switches between Files and Changes (palette Changes, or compi diff). Changes lists Unstaged and Staged files with their status letter and line counts, as a list or a tree. Click one to show its diff in that file's tab: each file has one tab, and a file with uncommitted changes has an Edit / Diff switch in its header (Ctrl+Shift+D, also Diff this file in the palette) that flips between editing and the diff at the same line; a file without changes shows no switch (an image, PDF or media file's first mode reads View). A tab showing a diff has a small diff icon, its tooltip names what it compares, and a staged diff says staged in its header. A deleted file opens only as a diff. Edits you have not saved stay in the editor while you look at the diff, which compares the saved file (the header says Unsaved edits not shown). Diffs show side by side when the pane is wide (switch with Auto/Unified/Split), highlight the changed words, fold unchanged lines (click a fold to show more, e expands everything) and search with Ctrl+F. n/p jump between changes, and [/] step through changed files. Each diff names what it compares (Working tree vs index, Index vs HEAD). Diffs and the list follow edits made anywhere, including in the terminal.

See changes while editing: Open files in a repository mark lines that differ from the index in the editor's left edge: a bar for added or changed lines, a small wedge where lines were deleted. Unsaved edits count. The tab row says vs index (or untracked). Click a mark or vs index to switch the tab to its diff there. Next change / Previous change (Alt+F5 / Alt+Shift+F5) move between changes. The marks only show changes; they never stage anything.

Stage and commit: Hover a file in Changes for + (stage), − (unstage) and ↺ (revert its uncommitted changes); the Unstaged and Staged headings stage or unstage everything. In a diff, hovering a change shows its Stage hunk / Unstage hunk button beside the first line (whitespace set to Exact); after n/p, Shift+S / Shift+U moves the current change. The header's Stage / Unstage (s / u) and Discard changes… act on the whole file. Reverting always asks first, lists each file, and deletes new (untracked) files; it can't be undone. Write the message in the box at the top of Changes and press Ctrl+Enter (Cmd+Enter on macOS) or Commit. Amend rewrites the last commit and loads its message. Hooks run as usual; if Git refuses, its message shows under the box.

Branches, fetch, pull and push: The top of Changes shows the branch (or detached at <commit>) and how far it is from its upstream, such as ↑2 ↓1; its tooltip says when it is up to date, and a branch without an upstream says no upstream. Click the branch (or use Switch branch… / Create branch… in the palette) to pick another one: type to filter, Enter switches, and the Create branch “name” row makes a branch at HEAD and switches to it. Remote branches switch to a new local branch that tracks them. Uncommitted changes come along; if they would be overwritten, Git's message shows in the picker and nothing is stashed or forced. Fetch, Pull and Push (buttons at the top of Changes, also in the palette) type git fetch, git pull or git push into a terminal beside the editor: one of that tab's terminals waiting at a prompt in the repository folder, else a new one opened there in the repository's environment, so password, SSH-key and 2FA prompts work. A branch without an upstream pushes with git push -u origin <branch>, and the Push tooltip says so. Nothing is ever force-pushed. The ahead and behind counts follow within a couple of seconds.

compi diff COMMIT shows a past commit (a hash, HEAD~1, a branch or a tag) at the top of the view's Changes sidebar: its short id and summary (author and age on hover), then the files it changed; × closes it. compi diff COMMIT FILE[:LINE] opens that file's diff in that commit, scrolled to LINE. A commit is compared with its parent (a merge with its first parent; the first commit shows every file as added), and nothing in it can be staged or discarded. With one argument, a file with uncommitted changes wins over a commit of the same name. An unknown commit, or a file the commit did not change, says so and exits 1. --json adds commit, short and summary.

Browser panes#

Keep your local app or documentation beside its terminal.

compi browse
compi browse localhost:3000
compi browse https://docs.rs --down

The local-server example requires something listening on port 3000. With no URL, the browser home page lists responding local servers found in terminal output and the last five sites for the window.

  • Ctrl/Cmd + L or F6 selects the address field; Enter navigates, Escape restores the current address.
  • Back, Forward and Reload/Stop use the pane’s toolbar.
  • Split, float, move or close it with the normal pane controls. Closing it does not stop a separate terminal’s server.
  • compi --json window list reports page URL, title, loading address and errors.
A pane is not browser automation.

Opening or navigating a Browser pane does not give an agent DOM inspection, screenshots or page automation. Those come from the agent’s own browser tools.

In 0.5.0, browser panes and PDF/audio/video previews remain visually unqualified on macOS. Web-view behavior and supported media formats depend on the platform.

Browser toolbar, profile, home page and CLI behavior

Open a web page beside a terminal: compi browse localhost:3000 (see below) or Open browser in the palette opens a Browser pane: a page of the system web view (WebView2 on Windows, WebKit on macOS) that splits, floats, moves and closes like any pane and comes back after a restart. The toolbar has Back, Forward, Reload (Stop while loading) and the address field: Ctrl+L (Cmd+L on macOS) or F6 selects it, Enter goes, Esc puts the current address back. A bar under the toolbar shows a page loading; a page that cannot load shows why, with Retry. Only http, https, file and about:blank addresses open; without a scheme http:// is assumed. Each instance keeps one browser profile, so sign-ins and cookies persist. The page hides while the palette, a menu or a dialog is open. On Windows a float above a page draws over it; on macOS the page hides while a float overlaps it.

Browser home page: a Browser pane without an address shows Compi's home page. Running here lists the local servers your terminals printed addresses for (a dev server's Local: http://localhost:5173/, for one) that are answering now, this tab's first, each with its tab's name. Recent lists the window's last five sites. Click one to open it; Back from the first page returns home.

compi browse URL opens URL in a Browser pane beside the selected terminal (below it with --down); the shell stays as it is. From a Browser pane (--pane), that pane goes to URL. Without a URL the pane opens on its home page with the keyboard in its address field: paste a link there to skip shell quoting (zsh, for one, stops at an unquoted ? or &). A pasted link may come with text around it, such as quotes, <…>, a Markdown link, a dev server's Local: http://localhost:5173/ line or a trailing period; Compi takes the link out of it. compi --json window list reports each shown Browser pane's page: its url, title, the address loading and the error of a failed load.

Agents and CLI#

Any agent that can run shell commands can use Compi’s public CLI.

Inside a supported Compi shell, the matching CLI is on PATH and inherits its instance and pane context. It operates the workspace around the agent; it is not an agent harness.

Discover, inspect, act, read back

compi --json help
compi --json pane show
compi run -- cargo test --locked -p compi-protocol
compi pane capture --scope scrollback --format text

The test command is for a shell in Compi’s source repository. run submits without waiting. Capture reads the output available so far; inspect or capture again to check progress. No fabricated success is returned on behalf of the running program.

Choose the exact target

Outside a Compi shell, choose an existing daemon with --instance NAME or --connect USER@HOST[:PORT]; --instance '' selects the default instance. Without a target, the CLI uses the only running local daemon and fails with the list of running instances when there are several, including older ones it cannot inspect. CLI commands do not start a missing daemon. Bare compi and compi PATH still open the GUI; inside a Compi shell they open the shell's instance, and a word that is neither a command nor a directory fails with a usage error suggesting the closest command (compi fiiles → did you mean 'files'?). Targets are stable --workspace ID|NAME, --tab ID|WORKSPACE/NAME, --pane ID|SURFACE_ID, and native --window ID; ambiguous names or windows fail rather than guessing. An explicit pane selects its containing tab/workspace, and explicit parent selectors replace incompatible inherited shell context.

Output and safety

In a terminal, workspace list, tab list, pane list and window list print tables, workspace show and pane show print name: value lines, layout list and theme install print a line or two, and tab focus, pane focus, pane zoom and the other window actions say what the window did. Long names, paths and addresses are shortened to fit the terminal; IDs always print whole so they can be copied. Piped or redirected, the same commands print indented JSON as before. --json always prints the same single line, in a terminal or not, so scripts and agents should pass it.

--json returns structured success/error envelopes. Full IDs remain copyable. Unknown commands fail with exit 2 instead of opening a GUI.

pane send --text is literal and does not press Enter. Use --key enter explicitly. Capture never takes input ownership. Interactive attach only accepts an unattached terminal and never steals a GUI attachment.

Close confirmations, output envelopes and exit codes

Close confirms interactively before ending live processes or discarding unsaved edits. pane close, tab close and workspace close ask the open Compi windows for files with unsaved edits in the content panes and terminals' Files views they would remove (with no window open there are none; if open windows cannot be asked, close fails with exit 1 and nothing closes), list each pane and file, and ask Close and discard unsaved changes? [y/N]; only y or yes closes. When processes would end too, one prompt names both and you type close. Noninteractive close returns exit 4 with code confirmation_required, and the --json error lists unsaved_files as {pane_id, path}; there is no --yes/--force bypass. Scripts must explicitly pane terminate, save or revert files in their window, inspect the resulting state, then close. --json emits {ok,result} or {ok,error}; stable IDs, lifetimes, revisions, metadata availability, and mutation receipts are available to automation. Exit codes: 0 success, 1 operation/transport failure, 2 arguments, 3 missing/ambiguous target, 4 confirmation, 5 unavailable daemon/attachment, 6 revision/generation/lifetime conflict. Run compi COMMAND ACTION --help for individual syntax.

Appearance and settings#

Configure the workspace without changing your tools.

Ctrl/Cmd + , opens Settings as a pane. Search finds controls across every section. From a terminal, use compi settings appearance.

Theme selects application and terminal colors together. Preview a tile, then Apply to keep it or Cancel to restore the current theme. An optional terminal-palette override lives under Advanced → Terminal colors.

Transparency, blur, opacity and fonts are independent preferences. Choose Comfy for rounded panes and gutters or Compact for edge-to-edge terminal space.

Themes, imports, exports and configuration example

Settings includes 41 bundled themes, including Compi Neutral, a restrained baseline for clear, blurred, or solid backgrounds. Theme selects application and terminal colors together. Advanced → Terminal colors defaults to Follow theme and allows an optional palette override; Appearance reports an active override. Existing Dark Glass selections, first-run defaults, and legacy split palettes are preserved.

Transparent background enables the opacity slider and Blur background toggle. Turning transparency off makes the window solid without forgetting opacity or blur preferences. Increase opacity on light or busy desktops, or turn transparency off for predictable contrast; very low opacity cannot guarantee readability against arbitrary wallpaper. Unsupported or reduced-transparency systems fall back to solid backgrounds automatically.

Settings → Appearance shows themes as tiles: the current theme first, then favorites and related themes, each with the Compi mark in its colors. Click a tile (or move with the arrow keys) to preview it on your panes; Apply (or Enter) keeps it and Cancel (or Esc, or leaving Settings) restores the previous one. All themes › opens the full list inside the Settings pane with search, All/Dark/Light/Favorites filters, a favorite star on each theme, and the same preview, Apply and Cancel. The applied theme stays first with a Current chip, even during search or preview; favorites follow, then remaining themes alphabetically. Advanced → Terminal colors → Choose override › uses the same list for terminal colors only. The list's ⋯ More menu holds import, export, attribution and removal. Import loads a local Zed .json theme family without applying or publishing it; each variant becomes a list entry. Export selected writes standard Zed JSON with existing attribution, license notices, and unused fields preserved. Remove local removes only an unused imported variant and its favorite, keeping sibling variants and the external source file; themes referenced by defaults, open windows, or previews are protected.

Theme files use Zed’s published JSON format: a family has name, author, and themes; each variant has name, appearance (dark or light), and style. No Compi ID, custom wrapper, or special filename is required. Import an unmodified downloaded file, such as Zed’s One Dark/One Light family, or export a bundled theme as a starting point. RGB/RGBA hex colors and missing/null style values are supported; missing colors use consistent light/dark defaults. Unknown fields are retained for export, not executed. Files are bounded to 2 MiB and 256 variants; invalid families and conflicting variants are rejected without partial installation.

Import copies the family into themes under Compi’s data directory. Copying a .json file directly into that directory also installs it without applying it; on Windows the directory is %LOCALAPPDATA%\Compi\themes. Theme code, includes, assets, and network resources are never executed or fetched. Existing managed .compi-theme.json imports migrate once, preserving their saved IDs, selections, favorites, colors, and attribution; verified originals are retained under .migrated. Transparency, opacity, and blur remain separate preferences, including when a Zed theme specifies its own background appearance.

compi theme install FILE.json uses this same validator and library without opening a window or applying the family. Supported WSL shells resolve relative Linux paths against the invoking cwd and install into the Windows application's data directory; --connect is rejected because installation is local application state.

Compact rounded-rectangle tabs use a subtle active fill, transparent inactive tabs, and a faint hover fill. Hover reveals a close button in a reserved slot without moving the label. Tab geometry, keyboard cycling, overflow, reorder, and tear-off are shared across themes.

Five interface-font choices apply globally to Compi's chrome and controls. Four terminal-font choices apply independently to the fixed-width terminal grid.

The native system fonts remain the defaults. Interface selection uses a stable bundled ID, while terminal selection updates the existing font.family setting:

[appearance]
ui_font = "ibm-plex-sans"
density = "comfy" # comfy (rounded panes with gaps) or compact (edge to edge)
theme = "compi-neutral"
terminal_theme = "dark-glass" # remembered optional override
terminal_theme_override = false # Follow theme; true enables the override
transparent_background = true
background_effect = "clear" # clear or blurred; legacy opaque still migrates
terminal_opacity = 0.7 # remembered background opacity, not text opacity

[font]
family = "JetBrains Mono"

Terminal presets include the platform default, JetBrains Mono, IBM Plex Mono, and Atkinson Hyperlegible Mono. Custom installed families remain supported through font.family. Bundled font notices and SIL Open Font License 1.1 text are in crates/compi-client/fonts/ATTRIBUTION.txt.

Settings → Interface → Pane density chooses how terminal panes sit in every window, independent of themes, prompts and transparency:

  • Comfy (default): each pane is a rounded island with an 8 px corner radius, separated from its neighbours and the window edge by 6 px gutters. The gutters use a slightly darker shade of the terminal background, or show the window material when the background is translucent. The header has no rule under it, and dragging a gutter resizes the split. The workspace sidebar is an island too; drag the gap beside it to resize it, or double-click the gap to restore its default width.
  • Compact: panes touch, separated by one-pixel seams, and the sidebar sits flush against the window edge, for the most terminal space.

When more than one pane is visible, the focused pane is marked as set under Focus indicator below; terminal colours are unchanged. Floating panes keep their shadow and title strip and use the same corner radius. Switching density resizes terminals through the normal resize path, so running programs keep running and reflow once.

Settings → Interface → Focus indicator chooses how the focused pane stands out when more than one pane is visible:

  • Marker (default): a short accent bar on the middle of the pane's bottom edge, plus an accent outline that fades within 0.8 s whenever focus moves to a pane.
  • Outline: a permanent accent outline.
  • Dim others: every other pane is slightly darkened.
  • None: only the cursor, which unfocused panes never draw.
[workspace]
focus_indicator = "marker" # marker, outline, dim, or none

Floating panes keep their Keyboard label with every option. When the system asks for reduced motion (Windows Animation effects off, or macOS Reduce motion), the arrival outline shows for the same time without fading; this is read when Compi starts.

Tab metadata

Settings → Interface → Tab metadata writes independent global caption/hover preferences:

[metadata]
directory = true
process = false
git = false
dimensions = false

A manual tab label takes precedence over automatic names. Enabled fields follow the focused pane, with a first-layout-pane fallback; pane count and dirty/stale indicators remain separate from truncated text. The hover card lists every pane in layout order. Collection uses the shell's actual Unix/WSL/SSH environment, caches results for five seconds, and marks stale/unavailable data explicitly. Disabling every field stops GUI metadata queries; CLI inspection remains available on demand.

Shell prompts

Settings → Terminal → Shell prompt uses your existing Oh My Posh or Starship installation in the environment where the shell runs. Compi does not install a provider or replace it with a native prompt renderer.

Prompt styles, applying, backups and restoration

Settings → Terminal → Shell prompt (or “Prompt settings” in the palette) styles the prompt your shells already draw with Oh My Posh or Starship. Compi does not install either one, has no prompt of its own, and uses each style exactly as the provider defines it. It works where your shells run: the local account, the WSL2 distribution you pick, or the SSH host.

  • Details shows where Compi is looking, your login shell, provider paths, startup-file lines that already set up a prompt, and any warning, such as an Oh My Posh installed only on Windows that cannot draw a WSL prompt. Bash and Zsh are supported. Fish, PowerShell, and custom launch profiles are not.
  • Pick a style: every style is listed with its real prompt rendered under its name: your current configuration first, then the provider default, Oh My Posh themes, or Starship presets. Browsing changes nothing, and the prompt is independent of the terminal theme and layout.
  • Apply: click a style and choose Apply in the popover under it, or Cancel. Compi shells use the style without any edit to your startup files; new ones start with it and running ones switch at their next prompt. Also use outside Compi additionally adds a marked # >>> compi prompt >>> block to the end of your login shell's ~/.bashrc or ~/.zshrc; the popover then shows that file's diff first. Nothing else in the file changes, and shells outside Compi need a new shell.
  • Back up, restore, turn off: each change backs up the managed files to ~/.compi/prompt/backups. History restores any of the last 20 backups and Turn off removes every prompt Compi manages, each confirmed in the same kind of popover. Your own provider configuration is copied, never edited.

Status and notifications#

See when supporting programs are working, blocked, finished or failed.

Programs report status through OSC 7501. Compi displays their reports instead of guessing from terminal output. Indicators can appear on tabs, panes and the sidebar; hovering shows the reported details.

Open Settings → Notifications or run compi settings notifications.

DeliveryBehavior
AutomaticIn-app cards while Compi is active; system notifications while it is in the background.
In-app onlyCards inside Compi.
System onlyOperating-system notifications.
BothBoth delivery paths for an eligible event.

Needs attention is on; Finished is off by default. Working, idle and failures do not generate notifications in 0.5.0. Existing reports are not replayed on reconnect. Click a card or notification to return to its terminal; dismissing a card does not clear program status.

Sound starts Off. On Windows choose Default, Message, Mail, Reminder or Text message, and use Play to preview. Quiet modes and system notification-sound settings are respected. Send test exercises the current delivery settings.

macOS notifications require the app bundle, request OS permission and have no sound in 0.5.0. They remain unverified on a Mac in that release.

Status lifecycle, indicator controls and notifications

Programs that support the Program Status Protocol (OSC 7501) report whether they are idle, working, blocked on you, done or failed. Compi answers their feature query, so programs that report only after asking work too.

  • A tab shows a glyph for the state that most needs you across its panes: blocked, then error, working, done and idle. Background tabs and other workspaces are included. A tiled pane shows a dot in its top edge, and a floating pane shows the glyph and progress in its title strip. The sidebar and palette put the state first in the tab's status line. Each of the three can be turned off under Settings → Interface → Program status (configuration).
  • Hover a tab for its full title, the state its panes most need you for, and each pane's name with every record it reported: program, title, state, what it waits for, progress and message. Hover a pane's dot or a floating pane's glyph for that pane's records alone.
  • Work in progress ends at the next shell prompt or when the process exits; finished and failed results stay until you press a key in that pane or close it.
  • compi --json pane list/show includes each terminal's program_status records.
  • Notifications: when a program in a terminal you are not using becomes blocked on you, Compi tells you (Settings → Notifications, configuration). Delivery picks where: Automatic (the default) shows a card at the bottom right of the window with that terminal while Compi is the active app, and a system notification while it is in the background; In-app only, System only and Both do just that. Needs attention (on) covers permissions, questions and sign-ins; Finished (off) covers programs reporting their work done. Failures, working and idle never notify, and neither does what a terminal already reported when Compi opened or reconnected. Clicking a card or a system notification opens that terminal, switching tab and showing the shell if a view covers it; × hides the card without clearing the status, which stays on the tab and pane. A program reporting again replaces its card. Sound (Off by default; Default, Message, Mail, Reminder or Text message, which are Windows' own notification sounds as your sound scheme sets them, with Play to hear one) plays your system notification sound once per notification: inside the system notification when there is one, otherwise from Compi with the card, and not while Windows is quiet (Do Not Disturb or quiet hours, presenting, a full-screen app, a locked screen) or its notification sounds are off. System notifications says whether the system shows Compi's notifications and opens its settings; Send test (also Test notification in the palette) sends one with your settings. On macOS, notifications need Compi to run from its app bundle, macOS asks for permission on the first one, and Compi plays no sound there yet.
Notification configuration

Settings → Notifications chooses when programs reporting through OSC 7501 notify you, and where. Changes made in Settings apply to every open window; edits to the file apply when Compi next opens.

[notifications]
delivery = "automatic"  # "automatic" (in Compi while it is active, else from the system), "in_app", "os" or "both"
attention = true        # a program is blocked on you: a permission, a question or a sign-in
finished = false        # a program reports its work done
sound = "off"           # or "default", "message", "mail", "reminder", "text_message": Windows' notification sounds, once per notification, unless Windows is quiet

Remote access#

Connect a native Compi client to an SSH host running a matching daemon.

compi --connect USER@HOST:PORT

Replace USER, HOST and PORT with your connection. The remote host must provide compi-daemon on PATH. Use a matching client/server release; SSH authentication and host-key checks remain part of the connection.

Reconnect to the same instance to reach the existing workspace. Reconnecting does not itself restart running shells. SSH transport is not automatic cross-machine workspace synchronization or a finished mobile app.

Remote launch and diagnostic client

Compi starts its sibling server automatically, and relaunching with the same instance name reconnects to that workspace. Use --working-directory PATH when you intentionally want new work to start in a specific directory.

To open the native client against an SSH host:

compi --connect dev@example.com:2222

The headless diagnostic client accepts the same --connect and optional --instance options. For example, compi-probe --connect dev@example.com workspace prints the remote hierarchy and lifecycle state, while its session, tab, pane, surface, soak, and shutdown commands operate through the same protocol. compi-probe tab arrange <tab-id> <preset> [--with <tab-id>]... [--main <pane-id>] [--mirror] [--flip], tab mirror|flip|restore-arrangement|split-merged <tab-id>, and pane swap <pane-id> <pane-id> rearrange existing panes in place; each --with merges another tab of the same workspace into <tab-id>. Presets are the built-in IDs (columns, rows, grid, main-side, main-top, equalize) or a [layout_presets] name from the local configuration. The remote host must provide compi-daemon on PATH.

Monitor#

Inspect the machine running the workspace’s server.

compi monitor
compi monitor sources
compi --json monitor totals --history 5m
compi --json monitor list --group

Overview, Processes, CPU, Memory, GPU, Disk and Network show the selected source. On Windows, choose the host or a WSL 2 distribution; their counters and PIDs are kept separate. An SSH-connected window monitors its remote host.

Select a process for its details, parent/children and recent resource history. Open terminal returns to its Compi terminal when available. Quit… and Force quit… both confirm and recheck process identity. Unavailable values are not zero.

Monitor pages, sampling and source selection

Monitor: Monitor in the palette (or the Monitor button in an empty window, or Open as pane in Settings → Monitor) shows the machine Compi's server runs on, in place of the focused terminal (see Views in place); if the window already has one, it is shown and focused. The rail on the left lists Overview, Processes, CPU, Memory, GPU, Disk and Network with live values (just icons when the pane is narrow; hover for the name). Overview shows a card for each with its history as columns of dots; click a card (or arrow to it and press Enter) for its page, Esc goes back. Cards rearrange into three, two or one column as the pane's width allows. Memory by type splits memory the way the system does: App, Wired, Compressed, Cached and Free on macOS, Used, Cached and Free elsewhere. Memory by app shows the apps using the most memory as tiles sized by it; click one to see its processes. The resource pages go further: CPU adds a bar per core; Memory shows in use, available, total, swap and pressure; GPU shows utilization and the GPU's memory (macOS and Windows; elsewhere it says it is unavailable); Disk lists your volumes with how full each is; Network lists each interface's current speed and totals, busiest first. The header picks the range the graphs cover (1m, 5m, 15m, 1h) and pauses them; history is kept for the last hour even while no Monitor is open. On Processes, Group by app gathers each app's processes (on macOS its helpers too) under one row with the app's icon and their totals; click the arrow, or press → and ←, to show or hide them. Type in the search field (Ctrl+F, Cmd+F on macOS) to match a name, command line, path, user or PID; All / Apps / My processes / System narrow the list (Apps is hidden where the system can't tell apps apart). Click a column heading to sort by it, again to reverse; CPU is a share of the whole machine. While the pointer is over the table the rows stay in place and only their values change, so a row doesn't jump away as you reach for it; moving off re-sorts. A dash means a value isn't available: macOS doesn't let Compi read some details of other users' processes. Processes are sampled every 2 seconds, only while the Overview (in a pane or in Settings) or Processes page is on screen.

Monitor a WSL distribution: On Windows the Monitor header has a source button listing the PC and each WSL 2 distribution; pick one to watch that distribution's CPU, memory, disk, network and processes instead. Each Monitor pane remembers its source, and a distribution's history starts when you open it. A window connected over SSH monitors that host.

Process inspection, quitting and saved columns

Inspect and quit processes: On Processes, select a row to see it in the inspector at the right (in a narrow pane, press Enter or double-click for a full page, and Back or Esc to return): its name and icon, PID, when it started and for how long it has run, state, user, app, working directory, executable and full arguments (Copy), its parent and children (click one to go to it), and its CPU and memory over the last 5 minutes. An app row shows the app's totals and its processes. Quit… asks the process to quit (SIGTERM; on Windows its windows are asked to close) and Force quit… ends it at once; both ask first, warn when it runs in a Compi terminal, and act only on that one process, and only if it is still the same process (a reused PID is left alone). Compi never quits itself, PID 0 or 1. Open terminal goes to the Compi terminal a process runs in. Right-click a row for the same actions plus Copy PID and Copy command.

Monitor columns: Drag the edge of a column heading to resize it, drag a heading to move it, and right-click the headings to hide or show columns or Reset columns. Each window remembers its columns; a narrow pane still hides User, then Threads, then CPU time.

Updates and repair#

Check for updates, understand restarts and recover an installation.

compi update --check

Use Settings → Updates to check, download and install. Nothing installs or restarts a daemon without your consent.

Updating to 0.5.0 restarts the local daemon.

Running shells end. Save your work first. Workspace format 8 carries over, but protocol 35 replaces 0.4.x’s protocol 34. The local updater does not restart remote daemons.

Windows users on 0.3.0 or earlier need to run the rebuilt 0.5.0 Setup once; the older helper cannot replace itself.

Update flow and activation recovery

Open Settings → Updates or run Check for Updates from the command palette. Check for updates is one switch, on by default; Download updates automatically is off by default, so nothing downloads until you click Download. Nothing installs, closes windows or restarts a daemon without a click. The page shows one status line and one button for the next step, sizes in MB, the notes for the available and running versions, and a dot on the sidebar button when an update is ready. After an update, the new version's notes appear once as a What's new card in the sidebar; fresh installs skip the card. Advanced holds Repair Compi and Open update log (.compi-update/update.log in the install folder).

An update that can keep the running daemon relaunches clients into their saved views without ending shells. If a local daemon restart is required, Compi asks for consent and ends its shells; save your work first. The local updater never restarts remote daemons.

Installing an update includes reopening Compi; starting the helper is not completion. Installation ownership is checked before windows close or a consented daemon stops. A failed activation or new-build attachment records the error and reopens the previous saved views when safe. If the previous views cannot reopen safely, the update journal and worker log retain the failure and recovery details.

See the current release notes for version-specific update instructions.

Updating from a terminal

compi update --check prints the running version and, when there is one, the newer release with its headline:

Compi 0.1.7 · 0.1.8 available
  WSL tab completion: 41.8 s → 0.07 s

compi update downloads and verifies the same signed package as Settings → Updates, on one progress line. It then lists the shells a restart would end, saying so when the shell you typed in is one of them, and asks Restart now? [y/N]. Only y restarts. The running Compi window performs the restart exactly as the Updates page does: it saves the windows, ends only the listed shells and reopens into the new version, so a listed shell running the command closes with it. With no window open, Compi opens first. Without an interactive terminal, for example from a script or agent, the command stops after the download with exit 4; restart from a terminal or Settings → Updates. There is no bypass. --json reports the same results, and builds without a release verification key report that updates are unavailable.

If the invoking shell survives the restart, the command waits for the new GUI to confirm attachment before reporting success. A helper handoff, rollback or unconfirmed reopen is not success. Successful --json output includes applied: true, reopened: true, restarting: false, the installed current version and the previous version.

Repair and removal

On Windows, Compi-Setup.exe --repair lists problems with the install (program files, unfinished updates, the background task and daemon, WSL) and fixes them one at a time or all together. In-app Repair Compi downloads the latest Setup and runs the same repair.

Repair logs to %LOCALAPPDATA%\Compi\doctor.log. Setup's other runs log to installer.log there, and Windows Installer's record of the latest run goes to installer-msi.log. Remove always removes the registered install, whichever Setup build runs it.

Upgrade, repair, rollback, and default uninstall preserve workspaces, settings, and custom themes. Maintenance offers a separate unchecked managed-data removal choice. External projects/configuration/theme sources and WSL distributions are not removed.

Troubleshooting#

Start with the affected environment and preserve the evidence.

Windows cannot start a shell

Confirm WSL2 is installed and the intended distribution starts. For a portable install, keep the entire archive together: the daemon requires its bundled terminal runtime. Use Setup’s repair path for installation problems.

A pane is disconnected or already attached

Use Reconnect window from the palette. It does not restart shells or steal another window’s attachment. Inspect compi --json pane show or open Diagnostics for the error. A process that ended is not restored merely by reconnecting.

A browser page will not load

Check the address and that the local server is listening, then use Retry. The Windows browser needs WebView2; browser/media behavior on macOS remains visually unqualified in 0.5.0.

A file changed outside Compi

Use the editor’s Reload / Keep mine / Overwrite choices deliberately. Recover unsaved buffers through Recover unsaved edits… in the palette. Do not discard a conflict just to clear the notice.

A notification makes no sound

Check Sound and delivery in Notifications, preview with Play, then check Windows notification sounds and quiet modes. macOS has no notification sound in 0.5.0. Supporting programs must report status; ordinary output does not create an event.

Collect a useful bug report

  • Compi version, operating system and whether the affected shell/files are on the host, WSL or SSH.
  • The exact action, expected result, actual result and a short reproduction.
  • Settings → Advanced → Performance → Copy diagnostics, or the palette’s Diagnostics action.
  • Relevant logs only, with tokens, private paths and other sensitive information removed.

Windows repair logs: %LOCALAPPDATA%\Compi\doctor.log. Setup logs are installer.log and installer-msi.log there. The update log is .compi-update/update.log in the install folder.

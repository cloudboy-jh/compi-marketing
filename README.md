# Compi website

Static HTML, CSS and JavaScript for Compi. No application framework or runtime dependencies.

## Build and check

```sh
npm ci
npm run build
npm run check
```

The build generates `docs.html`, validates local references on both pages and copies 16 allowlisted public files into `dist/`. Markdown rendering uses a pinned build-time dependency; the deployed site has no runtime package dependencies.

## Preview

After building, serve `dist/` with any static HTTP server, for example:

```sh
python -m http.server 8791 --bind 127.0.0.1 --directory dist
```

Open `http://127.0.0.1:8791` in a browser. Use `python3` instead of `python` where appropriate.

## Deploy to Cloudflare Pages

Requires Node.js and an authenticated Wrangler CLI with Pages access.

```sh
npm ci
npm run build
npm run check
wrangler pages deploy dist --project-name compi-marketing --branch main
```

Only `dist/` is deployed. The build checks local asset references and copies an explicit public-file allowlist, excluding design drafts, local skills and repository metadata.

Production: https://compi-marketing.pages.dev

This is a direct-upload Pages project. Pushing to GitHub does not automatically deploy it; run the deployment command after approving a change. Custom-domain attachment is separate.

## Documentation sources

`/docs.html` is a separate, searchable guide with desktop navigation and mobile Contents. Its HTML is generated by `tools/generate-docs.mjs` from the checked-in `content/0.8.1/` snapshots. The CLI reference comes from the release's actual `help.rs` catalogue, with provenance in `cli.json`.

The practical Work with agents guide comes from the product repository's `docs/user/AGENT_WORKFLOW.md`, copied unchanged to `content/guides/AGENT_WORKFLOW.md`. Keep those files identical when updating the guide. Positioning and workflow edits do not require rewriting the pinned release snapshots.

To refresh the pinned sources from a local Compi checkout:

```sh
node tools/import-docs.mjs PATH_TO_COMPI_REPOSITORY v0.8.1
npm run build
npm run check
```

For a new release, update the version in the generator as well as importing that tag, then delete the previous release's `content/` snapshot. Keep documentation claims tied to the published release, not development `main`. Do not edit generated `docs.html` directly. Shared `theme.js` keeps the saved appearance consistent between the landing page and documentation.

## Content and appearance

- Downloads and platform caveats are pinned to the published Compi 0.8.1 release.
- Neutral is the default appearance. Warm Carbon uses the original semantic colors from Compi's `crates/compi-client/themes/warm-carbon.json`.
- The workspace screenshot (`assets/workspace-full.png`) is a real capture of Compi 0.8.1 taken while building this page; `workspace-chat.png`, `workspace-diff.png` and `workspace-browser.png` are crops of it. Recapture rather than edit them, and update the crops and the hero legend's pane widths (`--chat-span` and siblings in `style.css`) together.
- `assets/compi-social-preview.png` is the 1280×640 social image used by both pages. It is identical to the product repository's `assets/compi-social-preview.png`.
- Screenshots are not recolored by the page appearance toggle. On phones, wide captures pan sideways instead of shrinking. Scrolling remains native.

01 / Agents

Bring the agents you already use.

Start Claude Code, Codex, OpenCode or any other terminal agent in a Compi terminal, in your project’s folder, with another terminal beside it for builds and tests.

Native chat, for OMP

compi chat or OMP chat in the palette swaps a terminal for a native conversation with OMP. Each tool call is one line. Permissions and questions arrive as cards. Attach files with @ and screenshots with paste, steer a running turn or queue the next message.

OMP keeps its own models, tools, settings and sessions. Compi supplies the view, and runs the chat in its background server so it keeps going when you close the window.

Native chat supports OMP in 0.8.1. Other agents keep their own terminal interface and work in the same workspace, through the same CLI.

02 / Review

Read the change, not the summary.

An agent’s report says what it meant to do. The diff shows what it did. Keep both on screen.

  • Changes lists unstaged and staged files with their line counts. Each file flips between Edit and Diff at the same line.
  • Stage a file or a single hunk, write the message and commit without leaving the workspace.
  • compi diff lets an agent bring its changes to you; compi diff HEAD~1 opens a past commit, read-only.

The diff reads files on disk. Unsaved editor changes are not part of it.

03 / Preview

The running app, next to the terminal running it.

compi browse 5173 opens your dev server in a Browser pane beside the terminal. It splits, floats and moves like any other pane.

When a terminal prints a local address, Compi can offer to open it. An empty Browser pane lists the local servers your terminals printed and your recent sites. Pages use the system web view and one persistent profile, so sign-ins stay.

A Browser pane shows the page to you. It does not give an agent DOM access, screenshots or automation; those come from the agent’s own browser tools.

04 / Terminals & CLI

Terminals that keep running. One CLI for you and your agents.

01

Close the window. The work keeps going.

Shells and chats live in Compi’s background server. Reopen Compi and reconnect to the same running processes.

02

Know when you’re needed.

Programs that report status show when they’re working, waiting on you, done or failed, even in a background tab. Compi can notify you and take you back to that terminal. Watch the notifications demo.

03

Arrange it around the task.

Tabs, groups, splits and floating panes rearrange without restarting what runs in them, locally or on a Compi server over SSH.

Closing the window keeps processes running. Restarting the server or rebooting ends them, and an update that needs a restart asks first.

From any Compi shell
  1. Inspect the workspacecompi --json pane list
  2. Make roomcompi split --right
  3. Read another terminalcompi pane capture --scope scrollback
  4. Show the changescompi diff
  5. Open the appcompi browse 5173

Any agent that can run shell commands can use these. Inside a Compi shell, compi is on PATH and knows its pane; --json returns structured results. Confirmations for closing live work stay in place.

Compi is the workspace, not an agent or an orchestrator. It doesn’t pick your agent or plan its work. CLI reference ↗
